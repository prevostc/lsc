# Internals

Decision records for people working on the language, compiler, and proofs.
User-facing narrative lives in [`docs/guide/`](../guide/). Product intent:
[`docs/PROJECT_GOAL.md`](../PROJECT_GOAL.md).

Token (S1, call-free) and Vault (S2, one external binding) anti-exploit
theorems are proved at bytecode (`token_bytecode_*`, `vault_bytecode_*`).
AMM has `amm_bytecode_no_unauthorized_extraction`; solvency is spec-level
(`amm_solvent`). Counter is compiler-level only.

- `LANGUAGE_ARCHITECTURE.md` — surface, Core, arithmetic domains, backend.
- `SECURITY_MODEL.md` — `Inv` / `claim` / `Auth`, adversary, language vs protocol.
- `INTERFACE_MODEL.md` — `Interface` / `Binding` / `Tx.call`, `Conforms` / `Rely`.
- `PROOF_CHAIN.md` — four links from a `Tx` theorem to bytecode.
- `MODULE_MAP.md` — `Lsc/` vs `Examples/`, `*Theorems` / `*Proof` / `*Defs`.
- `TRUSTED_COMPUTING_BASE.md` — what every end-to-end theorem trusts.
- `YUL_TARGET.md` — powdr Yul/EVM contract and Core → Yul mapping.
- `AMM_EXAMPLE.md` — identifier-dense AMM status (walkthrough: `docs/guide/AMM.md`).
- `DECISIONS.md` — dated decisions (S1/S2 strata; generated bytecode glue).

Keep them concise and decision-oriented. Changes to semantics, compilation,
trusted assumptions, or proof boundaries must update `PROOF_CHAIN.md` and
`TRUSTED_COMPUTING_BASE.md`.
