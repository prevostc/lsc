# Security Model

What "cannot be exploited for unauthorized wealth extraction" means in this project, and how it
is proved.

## Two layers

Protocol authors declare, per contract:

- `Inv : S → Prop` — the protocol invariant (e.g. `Σ balances = totalSupply`, `k` non-decreasing,
  `reserves ≤ token balances`).
- `claim : Address → S → ℕ` — what the protocol owes each account, in asset units (ERC20: balance;
  vault: redeemable assets; AMM: pro-rata share of reserves).
- `Auth : Address → Call → S → Prop` — who may reduce whose claim (the account itself, an
  allowance holder, a liquidator when under-collateralised, …).
- `holdings : World → ℕ` — assets the contract actually controls, read from the external-token
  model.

**Local obligations** — one per entrypoint `f`, generated by `lsc_contract`, proved by AI:

1. `Inv σ → Inv (post f)`
2. `claim a (post f) < claim a σ → Auth a call σ`
3. `Σ_a claim a (post f) ≤ Σ_a claim a σ + inflow call`

**Generic theorems** — proved once in `Lsc/Security`, over the trace semantics
`run : List Call → World → World` (any senders, any arguments, any order; a reverted call leaves
the world unchanged):

- `no_unauthorized_extraction`: for every account `a` and every trace containing no call
  authorised by `a`, `claim a` never decreases. This is the victim-side statement of "no
  unauthorized wealth extraction" (wallet-monotonicity).
- `solvency`: `Inv ⇒ Σ_a claim a ≤ holdings`, transported along traces.
- Trace induction for `Inv`.

Design decisions fixed for `Lsc/Security` (Trace / Invariant / Wealth):

- A contract is a `Spec` = finite `Fn` inductive + `entry : Fn → Entry` (own `Args`/`Ret` types,
  `run : Args → Tx`). A trace is `List (Call C)`; `step` is `Tx.run`, revert = identity;
  `run` is a left fold.
- `Auth` is evaluated in the **pre-state** of each call (allowances are state-dependent). The
  hypothesis of `no_unauthorized_extraction` is the recursive `NoAuthAlong Auth a tr w`
  ("`a` authorised no call, judged at the state where it ran"). Extraction does not need `Inv`.
- Obligations are stated **unpacked** per entrypoint (`PreservesInvFn`, `NoUnauthorizedDecreaseFn`,
  `ConservesFn` over `worldAfter (C.f args) ctx w`), never over dependent `Call`s; `of_fns`
  assemblers lift them. AI proves the unpacked forms with `simp [worldAfter, f, …]`, `split_ifs`,
  the `*_ok` lemmas and `omega`.
- Conservation is local: `∃ T : Finset Address` framing untouched claims and bounding
  `Σ_T claim` by the inflow. `inflow` is a spec function that is `0` on revert.
- `Mapping` stays `K → V` for now. Finite support is a ghost in `Inv`
  (`∃ H : Finset Address, (∀ a ∉ H, claim a = 0) ∧ Σ_H claim = totalSupply`). Switching to `K →₀ V`
  is a possible later Core/layout change, not an S1 requirement.
- Constructors are not trace entrypoints. A one-off `init_inv` theorem covers deployment from
  empty storage. Consequence found by this design: Token's `init` was a public `tx`; only a
  function named `constructor` is a constructor, so `init` must be renamed.
- `Trace.from A` (adversary address set) is available but unused by extraction; `Auth` is the
  victim-side filter.

## External contracts: the Interface model

- `World S E Ext` carries `ext : Ext`, a protocol-declared record of modelled external states
  (e.g. `asset : ERC20.State`).
- `Interface I := { State, Method, args, ret, abi, model : Method → args → CallCtx → State →
  Except CallErr (ret × State), laws : Prop }`.
- `Tx.call I lens m args` runs `I.model` deterministically on the lens. Proofs stay `simp`-shaped;
  repeated calls observe updated external state.
- `Conforms I addr` is the explicit deployment assumption: the code at `addr` realises `I.model`
  on every call from us and does not modify our account. The second half is justified by the
  reentrancy lock; its formal justification is a later milestone.
- `Implements C I` is a theorem for LSC contracts (Token implements ERC20).
- In `toYul_correct`, `letCall` is simulated under powdr's `ExternalsRealized` plus "responses
  follow the model".

## Adversary model

Any set of addresses `A`, any sequence of calls with arbitrary arguments from `A`, interleaved
arbitrarily with honest calls; external contracts behave per their declared interfaces.

Out of scope (stated in `TRUSTED_COMPUTING_BASE.md`): private-key compromise, block-producer
ordering/MEV, gas griefing, non-conforming tokens (fee-on-transfer, rebasing) unless modelled.

## Language-level guarantees (free, by construction)

No silent overflow; unit safety; reentrancy lock by default and read-only reentrancy check on
views; revert atomicity; frame theorems from `Core.effects`; no inline assembly, `delegatecall`,
`selfdestruct` or untyped calls; ABI/dispatcher correctness.

## Verified stdlib (proved once)

Security templates above; `Interface` machinery; ERC20 interface with laws (conservation,
transfer semantics); ERC20 core; share-vault core (rounding toward protocol, inflation-safe first
mint); constant-product AMM core (`k` monotone, pro-rata LP claim); `mulDiv` rounding suite;
AccessControl/Pausable.

## Protocol-specific

`Inv`, `claim`, `Auth`, `holdings`; which addresses are assumed to `Conform` to which interface;
economic parameters; prices and oracles.
